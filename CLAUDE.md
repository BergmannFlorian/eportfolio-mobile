# eportfolio_mobile

Mobile app (iOS + Android) that displays the content of the portfolio website
https://bergmann-florian.ch. The website is a separate SvelteKit project and must
not be modified from here: this app only **reads** its public JSON API.

## Working conventions

- Talk to the user in **French**. Code, comments, commit messages and docs are in **English**.
- If a need is not covered by the API (missing field or endpoint), **tell the user**
  instead of working around it: they will add it on the website side.
- Never try to enrich the data with private info (address, birth date, references).
- No app-specific backend: everything comes from the API, with a local cache for offline use.

## Commands and conventions

- After changing models, providers or the router, run `dart run build_runner build`.
- After changing ARB files, run `flutter gen-l10n`.
- Check every change with `flutter analyze` (expected: no issues) and `flutter test`.
- Generated files (`*.g.dart`, `*.freezed.dart`, `lib/l10n/generated/`) are committed.
- Material lives in the **`material_ui`** package since Flutter 3.47: import
  `package:material_ui/material_ui.dart`, not `package:flutter/material.dart`.
  - Localization delegates come from `material_ui` and `cupertino_ui`.
  - gen-l10n's `AppLocalizations.localizationsDelegates` still lists the deprecated
    `flutter_localizations` delegates, so `app.dart` declares the delegates itself.
- Riverpod 3: `Override` is in `package:flutter_riverpod/misc.dart`. Automatic retry is
  disabled in `ProviderScope(retry: ...)`, since errors are shown with a retry button.
- Visual check without a device: a throwaway widget test that loads the fonts with
  `FontLoader` and uses `matchesGoldenFile` with `--update-goldens` renders the screens
  to PNG. Do not commit it.

## Decided stack

| Concern | Choice |
| --- | --- |
| Framework | Flutter (Dart 3), targets iOS + Android |
| Navigation | go_router, `StatefulShellRoute` for the bottom tab bar |
| State | Riverpod 3 (with codegen), one `AsyncNotifier` per resource; locale is a provider all fetches depend on |
| HTTP | dio; `PortfolioApi.get(path, lang:)` adds `?lang=` and maps `{ error: {...} }` to typed `ApiException`s (network / HTTP status / invalid response) |
| Models | freezed + json_serializable, mirroring the TS types below; nulls are explicit |
| Offline cache | Raw JSON on disk, keyed by endpoint + lang, with fetch timestamp. Stale-while-revalidate: show cache immediately, refetch in background if older than 5 min (matches `max-age=300`), pull-to-refresh forces it. Offline banner shows cache date. |
| Preferences | shared_preferences: language (system / fr / en), theme (system / light / dark) |
| UI strings | gen-l10n with ARB files (fr, en) |
| Fonts | Questrial, Inter, JetBrains Mono **bundled as assets** (OFL), not the `google_fonts` runtime download |
| Misc | url_launcher, flutter_lints (strict), tests with mocktail + real JSON fixtures |

## Screens

Bottom tab bar with 4 tabs, plus settings from the app bar.

1. **Home**
   - Kicker, name, `headline`, `bio`.
   - Main stack chips.
   - Two separate featured blocks (`featured=true`): personal projects, then client projects.
     Each shows the first 3 by `position`, plus a "see all" cell.
   - Inverse "Contact" block (mailto + socials).
2. **Journey** (experiences)
   - Timeline with an All / Jobs / Education filter.
   - Experience detail: tasks, skill chips, linked projects.
3. **Projects**: two pages behind top sub-tabs, Personal (`experienceId == null`) and Client
   (all others).
   - Personal page: list of rich cards (badges, description, chips).
   - Client page: grouped by experience (section header links to it), 2-column numbered grid.
   - Both are sorted by `position`.
   - Project detail:
     - Badges for kind, status, year and hosting, each only when set.
     - Tasks, details, skills.
     - Snippet with a copy button, ↗ link, link to the parent experience.
4. **Profile**
   - `about`, facts, spoken languages with level bars, hobbies, socials.
   - Skills by category, sorted top → mid → bottom, with a recency legend and `*` for
     `personalOnly`.
   - Certificates.
5. **Settings**: language, theme, last sync date, app version.

Every screen handles these states:
- **Loading**: bordered skeletons.
- **Error without cache**: error message with a retry button.
- **Null fields**: the block is hidden, with no placeholder.

App language = system language (fr or en, else fr), overridable in settings, passed as `?lang=`.

## API

- Base URL: `https://bergmann-florian.ch/api/v1`. Use it **without** a trailing slash:
  `/api/v1/` returns a 308 redirect.
- `GET` only, no auth. Headers: `Access-Control-Allow-Origin: *`, `Cache-Control: public, max-age=300`.
- Language:
  - Sent as `?lang=fr|en`.
  - Fallbacks: the `Accept-Language` header, then `fr`.
  - The resolved language comes back in `Content-Language`.
  - All texts arrive already translated.
- Errors: `{ "error": { "status": 400, "message": "…" } }`.
  - `400`: invalid lang or filter.
  - `404`: unknown path.
  - `500`: database down.
- Raw JSON, no envelope. Dates are ISO `YYYY-MM-DD` (except `/cv`).

| Endpoint | Query | Returns |
| --- | --- | --- |
| `/api/v1` | | `ApiIndex` |
| `/api/v1/profile` | | `ApiProfile` |
| `/api/v1/experiences` | `kind=job\|education` | `ApiExperience[]` |
| `/api/v1/projects` | `featured=true\|false` | `ApiProject[]` |
| `/api/v1/skills` | | `ApiSkills` |
| `/api/v1/certificates` | | `ApiCertificate[]` |
| `/api/v1/cv` | | Internal `/cv` page format (`DD.MM.YYYY` dates, untyped). **Avoid**: prefer the endpoints above. |

### Types (source of truth)

```ts
type ApiLocale = 'fr' | 'en';
interface ApiError { error: { status: number; message: string } }
interface ApiIndex {
  name: string; version: 'v1'; locales: ApiLocale[]; defaultLocale: ApiLocale;
  endpoints: { path: string; description: string; query?: Record<string, string> }[];
}
interface ApiProfile {
  name: string; email: string; city: string; age: number;
  headline: string; bio: string; about: string; title: string;
  socials: { network: string; url: string }[];
  facts: { label: string; value: string }[];
  languages: { name: string; level: string; percent: number }[];
  hobbies: { name: string; reason: string }[];
}
interface ApiExperience {
  id: string;                   // stable, e.g. "job-iomedia-sa-2021-12"
  kind: 'job' | 'education';
  title: string; degree: string | null; organization: string | null;
  start: string; end: string | null; // YYYY-MM-DD, end null = ongoing
  tasks: string[]; skills: string[];
  projectIds: string[];         // -> ApiProject.id
}
interface ApiProject {
  id: string; name: string; url: string | null;
  image: string | null;         // internal key, no public URL: ignore
  featured: boolean;
  experienceId: string | null;  // null = personal project
  tasks: string[];              // description paragraphs
  details: string[];            // highlights
  skills: string[];             // technologies
  kind: 'website' | 'script' | 'app' | null;
  year: number | null;
  status: 'online' | 'in_progress' | 'archived' | null;
  hosting: string | null;
  snippet: string | null;       // usage example (shell command…)
  position: number;             // display order (1 = first); projects come sorted by it. Personal and
                                // client projects have separate numbering: group by experienceId
                                // (null = personal) before sorting.
}
interface ApiSkills {
  stack: string[];
  categories: {
    code: 'langs' | 'libs' | 'tools'; name: string;
    skills: { name: string; level: 'top' | 'mid' | 'bottom'; personalOnly: boolean }[];
    // level = how recently used; personalOnly = only used in personal projects (asterisk + legend)
  }[];
}
interface ApiCertificate { title: string; date: string; url: string | null }
```

### Known API gaps (reported to the user, 2026-11-24, not yet fixed)

1. **Project images**: `image` is an internal key, so cards are text-only.
   Needs an absolute `imageUrl`, ideally with width, height and alt text.
2. ~~Project order~~: solved by `position` (2026-11-24).
3. **Legacy projects**: `progcraft`, `runeo`, `websocket-notifications` and
   `intrepidknowledge-mobile-app` have empty `skills`, and their tech and duration are stored in
   `details`. Display them as-is; do not parse them.
4. **`profile.title`** contains `\r\n`. Normalize it to `\n` when displaying.
5. **No ETag or `Last-Modified`**, so no conditional requests. Acceptable given the small payloads.

Sober and editorial style:
- Square corners, thin borders.
- **No shadows, no rounded corners, no Material elevation or ripple tint.**
- A single brick-orange accent.

Fonts:
- **Questrial**: headings, regular weight, slightly negative letter-spacing.
- **Inter**: body text.

Recurring patterns:
- Two-line headings preceded by a mono kicker in the accent color.
- Cards in a grid with shared borders, mono number at the top left, and a ↗ arrow when the card has a link.
- Tech chips: thin border, mono 12 px text.
- Project status and kind shown as mono badges.
